## Context

`NotificationPublisher` (`pkg/notifications/publisher.go`) receives messages on an
internal channel and, in `handleBusMessage`, resolves subscriber chat IDs for the
message topic and sends the message to each. Topic-to-subscriber matching lives in
`getChatIdsForTopic`, which tokenizes `*` → `.*`, `regexp.QuoteMeta`s the rest, and uses
`re.MatchString` (unanchored).

There is currently no interception point between publish and delivery. This change adds a
topic-pattern hook system the publisher fires before fan-out.

## Goals / Non-Goals

**Goals:**
- A standalone `HookRegistrar` interface that owns hook storage, registration, and firing.
- The publisher fires matching hooks once per message before delivery.
- A sentinel `ErrCancelNotification` cancels a message; unknown errors fatal-log.
- Anchored topic matching so exact patterns match only the identical topic.

**Non-Goals:**
- Per-subscriber / per-chat hooks (hooks are per-topic only).
- Hook priorities, ordering guarantees, or async hooks. Hooks run synchronously in the
  bus goroutine in registration order.
- Changing existing subscriber matching semantics in `getChatIdsForTopic`.

## Decisions

### `HookRegistrar` as its own interface

```go
type Hook func(ctx context.Context, msg Message) error

type HookRegistrar interface {
    Register(topicPattern string, hook Hook)
    Fire(ctx context.Context, msg Message) error
}
```

A concrete `hookRegistrar` stores `[]struct{ pattern string; hook Hook }` (slice, not map,
to preserve registration order and allow multiple hooks per pattern). New file
`pkg/notifications/hooks.go`; mock generated by mockery into `hookregistrar_mock.go`.

`Fire` walks all entries, matches `msg.Topic` against each `pattern`, and invokes matching
hooks. It returns the first cancellation/error encountered so the publisher can act on it.

**Alternative considered:** folding hooks directly into the publisher. Rejected — the
requirement explicitly asks for a separate interface that holds all hooks and registration,
and separation keeps the publisher's fan-out logic untouched and the registrar unit-testable.

### Anchored matching (deliberate divergence from `getChatIdsForTopic`)

The existing subscriber matcher uses unanchored `re.MatchString`, so pattern
`weather.warning` would also match `weather.warning.severe`. That violates the requirement
that `weather.warning` hits only `weather.warning`. The registrar therefore anchors the
compiled pattern with `^...$`. Reuse the existing tokenize/quote/detokenize transform, then
wrap as `^` + pattern + `$`.

**Alternative considered:** reuse `getChatIdsForTopic`'s helper verbatim. Rejected because
it is unanchored and changing it would alter subscriber behavior (out of scope).

### Fire point: once, before the per-chat loop

In `handleBusMessage`, immediately after entry and before resolving chat IDs / the delivery
loop:

```go
if err := n.hooks.Fire(ctx, msg); err != nil {
    if errors.Is(err, ErrCancelNotification) {
        n.logger.Trace().Msgf("notification cancelled by hook: %s", msg.Topic)
        return nil
    }
    n.logger.Fatal().Err(err).Msg("unexpected error from notification hook")
}
```

Hooks are per-topic, so firing once (not per recipient) is correct. Cancellation returns
`nil` from `handleBusMessage` (a normal, non-error drop). The fatal branch matches the
requirement literally.

### Wiring and registration timing

Add a `hooks HookRegistrar` field to `NotificationPublisher`, default-initialized to a new
empty registrar in `NewNotificationPublisher`, with a `WithHookRegistrar(r HookRegistrar)`
`PublisherOptions` for injection/testing. Modules register hooks at wiring/init time
(before `Start`). The registrar still guards its slice with an `sync.RWMutex` (mirroring
`sublck`) so a `Fire` in the bus goroutine is safe even if a `Register` ever races.

## Risks / Trade-offs

- **Unknown hook error crashes the bot mid-handling** → This is the requested behavior, but
  it conflicts with the AGENTS.md guidance to reserve `Fatal` for init failures. Flagged in
  the proposal and the apply summary for confirmation; trivially switchable to `Error()` if
  the user prefers a loud non-fatal log.
- **Synchronous hooks block the bus goroutine** → A slow hook delays all notification
  delivery. Acceptable for the intended lightweight enrich/audit/suppress use; documented as
  a non-goal to make hooks async.
- **Anchored matching diverges from subscriber matching** → Two matchers with different
  anchoring could confuse future readers. Mitigated by a comment on the hook matcher noting
  the intentional difference and a spec scenario pinning the exact-match behavior.
